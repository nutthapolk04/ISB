ขั้นตอนแก้ไขปัญหา POS

จอ 2 (Customer Display) ไม่ปิดตามจอหลัก + Paywire EDC Bridge รันซ้อน
ระบบ: ISB POS Kiosk (campuscard.isb.ac.th)  |  อัปเดต: 2026-08-11  |  เอกสารภายในทีมเทคนิค

สรุปภาพรวม

เอกสารนี้รวบรวม 3 ประเด็นที่พบระหว่างทดสอบเครื่อง POS จริง พร้อมสาเหตุที่ยืนยันจากโค้ด และขั้นตอนแก้ไขทั้งฝั่งพัฒนา (แก้โค้ด/installer) และฝั่งหน้างาน (เครื่องที่ติดตั้งไปแล้ว)

ปัญหาผลกระทบสถานะการแก้ไข
1. จอ 2 ไม่ปิดตามจอ 1 / จอหลักสลับตำแหน่งตอนเปิดใหม่ รบกวนการปิด-เปิดเครื่องประจำวัน แก้โค้ดแล้ว — รอ deploy frontend
2. Paywire EDC bridge รันซ้อน 2 instance ทุกครั้งที่ boot รูดบัตรไม่ผ่าน/bridge ไม่ตอบสนองแบบสุ่ม แก้ installer + check-pos.ps1 แล้ว — รอ rollout เครื่องที่ติดตั้งแล้ว
3. โดเมน kiosk เปลี่ยนเป็น campuscard.isb.ac.th เครื่องใหม่เปิดผิดโดเมน / Chrome policy allow-list ผิดตัว แก้ installer + check-pos.ps1 + docs แล้ว — รอเช็ค nginx/SSL บนเซิร์ฟเวอร์แยกต่างหาก

ปัญหา 1 — จอ 2 ไม่ปิดตามจอหลัก MEDIUM

อาการ: กดปิดเบราว์เซอร์ (จอหลัก/จอ 1) แล้วจอลูกค้า (จอ 2) ยังค้างอยู่ พอเปิด kiosk ใหม่ หน้าต่างหลักไปโผล่ที่จอ 2 แทนจอ 1

สาเหตุที่ 1.1 — จอ 2 ไม่ปิดตาม

สาเหตุ ระบบไม่ใช่ Electron แต่เป็น Chrome kiosk (--kiosk) เปิดจอ 2 ด้วย window.open() ธรรมดา ถูกออกแบบให้จอ 2 ทนต่อการปิดโดยไม่ตั้งใจ (กัน Ctrl+W พลาด, watchdog reopen อัตโนมัติทุก 3 วิ) แต่ไม่เคยมี logic cascade-close จากจอ 1 มาจอ 2 เลย
frontend/src/pages/CustomerDisplay.tsx:69-76 (beforeunload guard)
frontend/src/lib/customerDisplayWindow.ts:69-81 (watchdog reopen)
การแก้ไข เพิ่ม effect ใน CustomerDisplay.tsx ที่ poll window.opener.closed ทุก 1 วิ — ค่านี้เป็น true เฉพาะตอนหน้าต่างหลักถูกปิดจริง (ไม่ใช่ reload/alt-tab เพราะ browsing context ยังอยู่ตอน reload) เมื่อตรวจพบจะปลด beforeunload guard แล้วสั่ง window.close() ปิดจอ 2 ตามอัตโนมัติ — ไม่กระทบพฤติกรรมเดิมตอน reload/alt-tab

สาเหตุที่ 1.2 — จอหลักสลับไปโผล่จอ 2 ตอนเปิดใหม่

สาเหตุ Chrome kiosk ถูกเปิดด้วย --kiosk เฉยๆ ไม่มี flag ระบุตำแหน่ง/จอ ตำแหน่งจึงขึ้นกับที่ Chrome profile จำ window bounds ล่าสุดไว้เอง — ถ้าครั้งก่อนหน้าต่างไปเลื่อน/ค้างอยู่จอ 2 (จาก crash หรือ sleep/resume) ครั้งถัดไปก็เปิดซ้ำตำแหน่งเดิม
pos-installer/installer.nsi (Chrome kiosk launch shortcut)
การแก้ไข เพิ่ม flag --window-position=0,0 ใน shortcut/Exec ที่เปิด Chrome kiosk — (0,0) คือมุมซ้ายบนของจอ primary เสมอตาม convention ของ Windows ไม่ว่าจะจัดวางจอยังไง บังคับให้ Chrome origin ที่จอ primary ก่อนเข้าโหมด fullscreen ทุกครั้ง

ขั้นตอน Deploy

  1. Deploy โค้ด frontend ที่แก้ไข (frontend/src/pages/CustomerDisplay.tsx) ขึ้น production ที่ campuscard.isb.ac.th — จำเป็น เพราะเป็นโค้ดฝั่งเว็บที่ kiosk โหลดจาก URL จริง
  2. เครื่องที่ติดตั้ง ใหม่: ใช้ installer ตัวล่าสุด (ISB-POS-Setup-1.0.0.exe ที่ build ใหม่แล้ว มี --window-position=0,0 ติดมาด้วย)
  3. เครื่องที่ติดตั้ง ไปแล้ว: รัน check-pos.ps1 เวอร์ชันล่าสุด (ดูขั้นตอนใน "Rollout เครื่องที่ติดตั้งแล้ว" ด้านล่าง) — จะซ่อม kiosk shortcut ให้มี flag นี้โดยอัตโนมัติ

Checklist ทดสอบ

ปิดจอ 1 (Alt+F4 / ปิดเบราว์เซอร์จริง) → จอ 2 ปิดตามภายใน ~1 วินาที
กด F5 (reload) หรือ alt-tab บนจอ 1 → จอ 2 ยังอยู่ปกติ ไม่ปิดตาม
รีสตาร์ทเครื่อง/เปิด kiosk ใหม่ → จอหลักเปิดที่จอ primary ถูกต้องทุกครั้ง

ปัญหา 2 — Paywire EDC Bridge รันซ้อน 2 instance HIGH

อาการ: เปิดเครื่อง/login ตามปกติ (ไม่ได้รัน installer หรือ script เอง) แล้วพบ paywire.exe รันอยู่ 2 process พร้อมกันใน Task Manager

สาเหตุที่เป็นไปได้

สาเหตุ (รอผล diagnostic ยืนยัน) มี autostart entry ชี้ไป paywire.exe ซ้อนกันมากกว่า 1 จุด ทั้งสองยิงตอน login พร้อมกัน — installer ตั้งใจสร้างแค่ Startup shortcut แบบ all-users จุดเดียว (installer.nsi:100-102) จุดที่อาจซ้ำได้แก่:
  • Startup shortcut ที่ current-user scope (เหลือจากติดตั้งเวอร์ชัน/รอบก่อนหน้า)
  • Registry Run key (HKCU หรือ HKLM) — บางซอฟต์แวร์ POS/EDC bridge self-register auto-start ไว้ในตัวเอง
  • Scheduled Task ที่ชี้ไปที่ paywire.exe
ผลกระทบที่แท้จริง ไม่กระทบเรื่องเงินโดยตรง (USB device แบบ exclusive lock ทำให้รูดบัตร 1 ครั้งไม่มีทางตัดเงินซ้ำ 2 รอบ) แต่ทั้ง 2 instance แย่งกัน bind port 7331 และแย่งสิทธิ์คุมเครื่อง EDC — ตัวที่แพ้จะทำให้เกิดอาการ "รูดบัตรไม่ผ่าน / bridge ไม่ตอบสนอง" แบบสุ่มทุกครั้งที่ boot
การแก้ไข อัปเดต check-pos.ps1 ให้ self-heal อัตโนมัติทุกครั้งที่รัน:
  • ลบ Startup shortcut ซ้ำที่ current-user scope
  • ลบ Run key ใน registry (HKCU/HKLM) ที่มีคำว่า "paywire"
  • ลบ Scheduled Task ที่ชี้ไป paywire.exe
  • ถ้าพบ process รันซ้อนมากกว่า 1 → kill ทั้งหมดแล้วเปิดใหม่ให้เหลือตัวเดียว
  • สร้าง Startup shortcut มาตรฐาน (all-users) ใหม่ถ้าหายไป

Rollout — เครื่องที่ติดตั้งไปแล้ว

ไม่ต้อง reinstall ทั้งชุด (เสี่ยงกว่า ต้องรัน driver installer ซ้ำ) — copy ไฟล์เดียวพอ:

  1. Copy ไฟล์ pos-installer/check-pos.ps1 (เวอร์ชันล่าสุด) ไปทับที่ C:\ISB\check-pos.ps1 บนเครื่อง POS
  2. เปิด PowerShell แบบ Administrator แล้วรัน: 
    cd C:\ISB
powershell -ExecutionPolicy Bypass -File check-pos.ps1
  3. อ่าน log ที่ script พิมพ์ออกมา — จะบอกชัดเจนว่าลบ/แก้อะไรไปบ้าง
  4. ทำซ้ำกับทุกเครื่อง POS ที่ deploy ไปแล้วในสนาม

Rollout — เครื่องติดตั้งใหม่

ใช้ ISB-POS-Setup-1.0.0.exe ตัวล่าสุดที่ build จาก pos-installer/build.sh — มี fix นี้รวมอยู่แล้วตั้งแต่ครั้งแรกที่ติดตั้ง ไม่ต้องรัน check-pos.ps1 เพิ่ม

Checklist ทดสอบ

รัน check-pos.ps1 แล้ว log แสดงผลลัพธ์ครบทุกหัวข้อเป็น OK
Task Manager เห็น paywire.exe เหลือ 1 process เท่านั้น
รีสตาร์ทเครื่อง 2-3 รอบติดกัน → เช็คซ้ำว่ายังเหลือ 1 process เสมอ (ไม่กลับมาซ้อนอีก)
ทดสอบรูดบัตรจริงผ่าน EDC → ผ่านปกติ ไม่มี "bridge ไม่ตอบสนอง"

ปัญหา 3 — โดเมน kiosk เปลี่ยน (campuscard.isb.ac.th) MEDIUM

อาการ: kiosk ต้องเปิดไปที่ https://campuscard.isb.ac.th/login แต่ installer/สคริปต์เดิมยังชี้ไปที่โดเมนเก่า isb.schooney.tech

สาเหตุ ย้ายโดเมนแล้ว (DNS/proxy เปลี่ยนมาชี้ campuscard.isb.ac.th) แต่เซิร์ฟเวอร์/CSP เบื้องหลังยังเป็นตัวเดียวกับ isb.schooney.tech เดิม — ไฟล์ installer, check-pos.ps1 และเอกสารประกอบยังฝัง URL/policy เดิมไว้ ทำให้เครื่องที่ติดตั้งใหม่เปิด kiosk ผิดโดเมน และ Chrome policy (LocalNetworkAccessAllowedForUrls / PopupsAllowedForUrls) ก็ allow-list โดเมนผิดตัวด้วย
การแก้ไข แทนที่ isb.schooney.tech ด้วย campuscard.isb.ac.th ในไฟล์ operational ทั้งหมด — installer.nsi (kiosk launch URL + ทั้ง 2 Chrome policy), check-pos.ps1 (kiosk shortcut check/repair + policy check), README.md, README.txt, INSTALL-GUIDE.html

จงใจไม่แตะ pos.local.bridge.schooney.tech:7331 (loopback hostname ของตัว Paywire bridge เอง คนละตัวกับโดเมนแอปหลัก ไม่เกี่ยวกับการย้ายโดเมนนี้) และไม่แตะ docs/edc/FIX-CSP-EDC-BRIDGE.md กับ EDC-CONNECT-GUIDE.html เพราะเป็น incident log ที่ลงวันที่/quote curl response ไว้ ณ ตอนเกิดเหตุ (16 ก.ค. 2026) — แก้ย้อนหลังจะทำให้บันทึกประวัติศาสตร์ผิดเพี้ยน

สิ่งที่ต้องเช็คเพิ่มนอกเหนือจากโค้ดในนี้

เป็น domain migration ของ DNS/proxy ที่ชี้เซิร์ฟเวอร์เดิม — nginx config และ CSP header เองไม่ได้อยู่ใน repo นี้ ต้องเข้าไปเช็คบนเซิร์ฟเวอร์จริงแยกต่างหาก:

nginx server_name ครอบคลุม campuscard.isb.ac.th แล้ว
SSL certificate ครอบคลุมโดเมนใหม่ (ไม่ขึ้นเตือน self-signed/expired ตอนเปิด kiosk)

Checklist ทดสอบ

เปิด kiosk บนเครื่องที่ใช้ installer/check-pos.ps1 ตัวใหม่ → landing ที่ https://campuscard.isb.ac.th/login ถูกต้อง
chrome://policy แสดง LocalNetworkAccessAllowedForUrls และ PopupsAllowedForUrls เป็น campuscard.isb.ac.th
ทดสอบ EDC bridge เชื่อมได้ปกติ (ไม่ถูก CSP บล็อก) หลังเปลี่ยนโดเมน
